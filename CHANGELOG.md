# Changelog

## Unreleased

### Fixed

- botsun-owner: a retry of a long video that arrived while its copy and hash were still running was answered `duplicate`, and the phone dropped its only copy; if the frames then failed, the message was lost. The id's in-progress mark went in only once the take was done, so during those seconds `onItsWay` was empty. It is set the moment the take starts now, and a retry keeps waiting while the id is still on its way (a take hands its mark over to its frames when it replies) rather than going in as soon as the reply is out. Tests: `test/botsun-owner.test.mjs` (a retry dispatched in the same tick as the take waits for it and goes in when that delivery fails; without the mark it was answered `duplicate`).
- botsun-owner: a phone `/compact` sent mid-turn reported "ran" while it was only held for the settle. With a stale busy flag (pi already idle) nothing ran at all, and after a session switch it could compact the conversation that took the old one's place. It now answers `delivered: "held"`, runs at once when pi is really idle (`ctx.isIdle()`), remembers the conversation it was sent in (dropped when another one starts) and is cleared on `session_start` as well. Tests: `test/botsun-owner.test.mjs` (a busy /compact is held and runs at the settle; a stale busy flag runs it at once; one queued in another conversation never runs).
- botsun-owner: an upload that doesn't start like a movie, sent while an earlier video's frames were still coming, was injected ahead of it: `deliverSay` chained an `inOrder` reply only when one of its files was a video. Any upload reply with an `after` is chained now. Tests: `test/botsun-owner.test.mjs` (a non-movie upload waits behind a gated video's frames).
- botsun-owner: the owner socket's longer 35 s idle timeout was given to any say naming a message id, before its signature was checked, so a local caller could hold an owner socket 7x longer than anything else. It is applied only once the signature holds (and its nonce is spent), through a callback from the socket handler; `idleTimeoutOf` is gone. Tests: `test/botsun-owner.test.mjs` (an unsigned say keeps the short timeout; a signed one lengthens it).
- botsun-owner: `takeUploads` chmod'd each copy to `0600` after the hash even though `copyUpload` already creates it `0600`; the mode is never loosened, so the call and its comment are gone.
- tmux-attention: attention is raised on every `ui_prompt_start` again, not only when the tracker's state changes. A focus-in clears `@special_activity` while a dialog is still open, and a second dialog opening on top changed no state, so it left the window unflagged. Tests: `test/tmux-attention.test.mjs`.
- botsun-owner: a `<pid>.json` left by a dead pi whose pid this process reused still named the session in its prompt and on the phone. A hard exit skips agent-link's cleanup, and the file says exactly what ours would (`pid === process.pid`, `entrypoint: "pi"`), so the pid check couldn't tell them apart. `linkEntry` now also ignores a file whose `startedAt` is earlier than this process's start (a second's slack for a clock that moved under it), the check `extensions/footer` already reads the same file with. Tests: `test/botsun-owner.test.mjs` — the fixtures now write our own pid with an hour-old start time; the old ones wrote `pid + 1` into our own pid's file, which can't happen, so they passed without testing the claim.
- botsun-owner: a retry of a message that was still on its way could be a lost message. The id is marked in progress before the take, so a retry during a video's hash or its frames was answered `duplicate` — which the phone treats as delivered — even if that delivery then failed (the `.part` gone after Botsun gave up, an inject that throws). `saidPending` is a Map of id to the promise that settles when the delivery does, and a retry with the same id and digest awaits it: it is a `duplicate` if that went in, and is delivered if it failed (the id is forgotten by then). An id's mark is cleared only by its own delivery, and only while that digest is still the one recorded, so a finished older message can't unpin a newer one reusing the id. Tests: `test/botsun-owner.test.mjs` (a retry of a gated video waits and is then a duplicate; a retry whose first delivery failed goes in; the old timing-dependent 32 MB test is replaced by the gate).
- botsun-owner: a queued take could outlast the owner socket's 5 s idle timeout. `deliverUploads` chained the take behind `c.framing`, so a video's reply waited for an earlier video's ffmpeg (up to 20 s) plus the hash before Botsun closed the connection — the say went in later, with nobody to answer. The take starts at once (hashing Botsun's own file needs nothing from the queue) and only the inject waits behind the earlier frames (`deliverSay`'s `after`); the queue is still held from the moment the take starts, so words sent during the hash go in behind the video. The socket's idle timeout is now 35 s for a say carrying uploads, or a message id (a retry of one may wait for a delivery still going), and 5 s for anything else, set through one handler so a longer value can't leave the old one in place. Tests: `test/botsun-owner.test.mjs` (`idleTimeoutOf`: 5 s for words alone and every other request, 35 s for uploads or a message id).
- botsun-owner: a `files:` video (a small mp4, not on the long-video path) whose frames failed kept its id, so every retry was answered `duplicate` and the message was lost; the earlier fix covered uploads only. `deliverSay` takes an `onFail` now, called when its frames throw, and the say path passes `saidForget`. Tests: `test/botsun-owner.test.mjs` (a throwing inject for a `files:` mp4's frames leaves no id behind, and the next try goes in once).
- botsun-owner: a say whose delivery failed left the copies it took behind (up to 512 MB each, and another with every retry). They are unlinked now: an upload's when its frames fail, and the files `deliverSay` saved when its delivery throws or its frames fail. A take whose inject threw also left the framing queue held, so every later say waited behind a queue that never opened; it is let go. And `copyUpload` loops over `bytesWritten` instead of assuming the whole chunk went, so a copy can't differ from the bytes hashed. Tests: `test/botsun-owner.test.mjs` (a say pi throws on leaves an empty inbox and the words after it go in; a failed retry leaves one copy, the one that went in).
- botsun-owner: a retry after Botsun removed its `.part` was answered "an upload must be in Botsun's uploads dir" rather than `duplicate`. The duplicate check now runs before the uploads' disk checks (still after the signature, so an unsigned caller learns nothing). Tests: `test/botsun-owner.test.mjs`. Also, the comment on `checkUploads` no longer claims no path part can be swapped: `O_NOFOLLOW` guards the file itself.
- subagent, children: a peer's `rename` frame (any local peer can send one) could put a bidi override or a zero-width character into a child's `PI_SUBAGENT_PARENT`, and the background progress log's `· message in · from <who>` line copied them into the log, since `clean()` stripped control characters only and the filter's `short()` stripped neither. Both strip `[\p{Cc}\p{Cf}]` now (as agent-link's `peerWords` already did), so a name can't rewrite or hide the line it lands in. Tests: `test/subagent.test.mjs`.
- agent-link: a receipt's reason is cut by code point, not by UTF-16 unit, so a long reason never ends in half a surrogate pair (which Swift's and Ruby's JSON can reject). Tests: `packages/agent-link/test/delivery.mjs`.
- botsun-owner: a folder-derived or a foreign registry name named the session in its system prompt, and a foreign one on the phone too. `identityName` read agent-link's `~/.claude/sessions/<pid>.json` and took any non-empty `name`, but that folder is keyed by pid and shared with Claude Code: a file left by a crashed process whose pid was reused, or another tool's, could name this session, and agent-link always writes a name (derived from the folder, `nameSource: "derived"`, when the session has none) and re-picks a derived one as sibling sessions come and go. One `linkEntry()` now reads the file for both names and ignores it unless `raw.pid === process.pid` and `raw.entrypoint === "pi"`, and `identityName` ignores a derived name (so an unnamed session's prompt claims no name, and a derived name that changes doesn't resend the section); `currentName` still shows the derived name on the phone. Tests: `test/botsun-owner.test.mjs` (the fixture is what agent-link writes; another pid's file, Claude Code's file and a derived name each name no section, a derived name still reaches the phone, and this pi's own entry still wins).
- botsun-owner: a text say sent while a long video's frames were still being pulled could be injected ahead of the video. The take's job is the framing queue, but `deliverSay` in `inOrder` mode started the frames from a resolved promise, set `c.framing` to that job and answered at once, so the take's own queue mark resolved while ffmpeg was still running and the words chained behind it went in first. `deliverSay` now hands the frames' promise back on its reply (under a symbol, so the phone never sees it) instead of touching `c.framing`, and the take holds its queue mark until the frames are in (the take starts at once, so the reply doesn't wait for an earlier video's ffmpeg either: see above). Tests: `test/botsun-owner.test.mjs` (words sent during a 32 MB hash stay behind a gated frame extractor and go in after the video).
- botsun-owner: a delivery that threw left the phone's message id recorded, so every retry was answered `duplicate` and the message was lost. `deliverSay` is now called in a `try`, and a promise it returns has a rejection handler too; either way `saidForget` runs before the failure is rethrown, and a video whose frames' delivery fails in the background forgets its id as well. Tests: `test/botsun-owner.test.mjs` (a throwing `inject` for words and for a video's frames leaves no id behind, and the next try goes in).
- botsun-owner (hardening): the upload copy opens the file by its basename in the uploads directory `checkUploads` realpath'd (so no path part can be swapped after the check) with `O_NONBLOCK` added (a FIFO can't hold a libuv worker thread), reads no further than the size signed (a `.part` that keeps growing can't fill the inbox), and unlinks its own file only once it was actually opened (`EEXIST` leaves the file there alone). Also: an in-progress message id is no longer evicted from the 64-entry memory, so a retry of a big video that is still hashing waits for that delivery instead of being answered `duplicate` for one that may still fail. Tests: `test/botsun-owner.test.mjs` (the real directory is handed back; 64 delivered ids don't evict a video's in-progress id).
- agent-link: a peer's words in a receipt also lose their format characters (`\p{Cf}`: bidi overrides, zero-width characters and look-alike marks), not just control characters and quotes. Tests: `packages/agent-link/test/delivery.mjs`.
- botsun-owner (security): a long video is copied into the inbox, never hard linked to Botsun's file. A link let anything that could still write to Botsun's copy change the video after the hash check, a `.part` could be swapped for a link between the check and the link, and `chmod 0600` on the link changed the mode of whatever file was behind it even when the say was then refused. The upload is now opened with `O_NOFOLLOW`, checked with `fstat` to be a plain file with a single link and the size signed, then copied into a new `0600` file and hashed as it copies; the copy's mode is set only after the hash matches, and `linkSync` is gone. Tests: `test/botsun-owner.test.mjs` (a `.part` that is a hard link to another file is refused and leaves that file's mode and bytes alone).
- botsun-owner (security): the same say could be delivered twice. Its message id was recorded only after `takeUploads`, so a retry with the same `client_id` and a fresh nonce could pass the duplicate check while the video was still being hashed, giving two inbox copies and two injected messages. The id is now recorded as in progress before the take and forgotten if the take or the delivery fails, so a retry is answered `duplicate` and a failed one is still delivered when the phone tries again. Tests: `test/botsun-owner.test.mjs` (a retry during a 32 MB hash is a duplicate and the video goes in once; the same id after a refused take is delivered).
- botsun-owner: an unsigned caller could probe the uploads folder. `uploadsOf` read the disk before `verifyDevice`, so the error text said whether a `.part` file existed and how big it was. The path and size checks now run after the signature (`uploadsOf` is shape only, `checkUploads` the disk part), so a bad signature gets the same answer either way. Tests: `test/botsun-owner.test.mjs`.
- botsun-owner: an upload's name is capped at 200 bytes of UTF-8, not 200 characters (200 three-byte characters plus the inbox's stamp went past a filename's 255 bytes and failed with `ENAMETOOLONG`). Tests: `test/botsun-owner.test.mjs`.
- botsun-owner: a text say sent while a long video was being taken could be injected ahead of it, since `c.framing` was set only later in `deliverSay`. The take and the delivery are now one job on the framing queue. Tests: `test/botsun-owner.test.mjs` (words sent during the hash go in behind the video).

And the background progress log's `· message in ·` line copied 110 characters of a framed peer message into the log the parent's model reads: it now says `· message in · from <who> (a peer's words, not your user's)` and never the text. Tests: `test/subagent.test.mjs`.

- agent-link, subagent, auto-session-name: a message sent to a subagent is reported delivered only once it is in the child's conversation. Before, `send` said "Delivered" as soon as the frame reached the child's socket. pi's print mode does read a steer that arrives mid-run, at the next turn boundary (checked live: it shows in the child's JSON as a `user` `message_end`), but the parent's views (the bg progress log and the children transcript) only show assistant messages, so nothing showed it; and a message that arrived before the run or after it ended started a run that the exiting process cut off, still reported "Delivered". Now `send` between pi sessions waits up to 5 s for a second receipt, sent when the receiver's `message_start` shows the message (matched by a `ref <nonce>` in its header), and says "Delivered into its conversation", or "Received but not yet in its conversation (it may be finishing; the message is queued)" with a later notice if it's dropped; a print-mode session outside its run refuses with "… is a print-mode subagent and can't take messages: its run has ended. Start a new task instead.". A pi child of the subagent tool gets `PI_SUBAGENT_TITLE` (its task title) and `PI_SUBAGENT_PARENT` (this session's agent-link name, else its session name), registers under the title, is listed as `<title> (subagent of <parent>)` (`subagent: true` in the list's `details.sessions`) and answers to it as a `to` or an `@mention` (`@pill-face-esc`); auto-session-name no longer renames such a child. The background progress log shows a message steered in mid-run as `· message in · …`. Tests: `packages/agent-link/test/delivery.mjs`, `packages/agent-link/test/subagent.mjs` (both now in `npm test`), `test/subagent.test.mjs`, `test/auto-session-name.test.mjs`.

Each tick rewrites `sections.json` with a fresh `at` for the hidden `auto-jobs` entry. - canvas: a settled turn no longer holds up every extension that settles after it, and no longer re-diffs every tracked file. pi awaits each `agent_settled` handler in load order (`extensions/*` before `extensions/opt-in/*`, so canvas before botsun-owner), and canvas's ran `writeReply`/`writeInfo` (a `getBranch()` over the whole session, 210 MB in a long one) and then `updateWidgets`, which for every file ever tracked ran `spawnSync git diff --no-index` and rewrote its patch: on a session with 368 tracked files that was 5–13 s before botsun-owner could write `idle`, so the phone showed "Thinking…" and no Next-steps buttons long after the run ended. The handler now keeps only its cheap bookkeeping (`track`, `turn.json`) and defers reply, info, the widget cards and the status run with `setTimeout(…, 0)` (a macrotask, so the later handlers run first; the serial order among the widgets is unchanged, `liveNested` is taken at once, and the deferred piece does nothing if the session switched meanwhile). Files changed and other cards, `reply.json` and `info.json` now update a tick later than the settle. `updateWidgets` records each file's `mtimeMs`/`size` in its `auto-diffs.json` entry and re-diffs only files whose stamp moved or that this turn edited (an old entry has neither and is diffed once), runs those diffs with `execFile` at most four at a time instead of blocking, and writes a patch, `auto-diffs.json` or `auto-copies.json` only when the text changed (an identical rewrite still moves the folder's mtime, which defeats the page's plan cache). The settled turn and its ops are read in the handler, before the timer: a run that starts first (botsun-owner's `afterStop`, the scheduler, goal, agent-link) has already put its user entry on the branch, and `lastTurn` would then hand back that new, empty turn, so the finished turn's edits never reached Files changed. The `auto-diffs.json` re-read before the write merges only the four fields the pass measured (`adds`, `dels`, `mtimeMs`, `size`) into entries still there, so an entry a concurrent write refreshed keeps its own `base`/`patch`/`skip` and one the prune deleted stays deleted (it pointed at a `base-*` that was gone, so its diff would have failed from then on); a diff that fails records its stamp too, so it is retried when the file changes rather than on every settle, and the Files changed card is built from the merged read rather than the pre-diff one. Tests: `test/canvas-settle.test.mjs` — a second settle over 12 tracked, unchanged files spawns no `git diff` (counted by a `git` on PATH that logs its arguments) and leaves every patch's mtime alone, and only a file that changed is re-diffed after it; a handler registered after canvas's sees the handler return in under 50 ms with no diff started and no `reply.json` yet, while the deferred work lands a tick later; a run that starts before the deferred work does (a user entry appended to the branch right after the settle) still gets every edited file in `auto-files.json` and the card; and a `git` that rewrites `auto-diffs.json` mid-diff (one entry's `base` changed, another deleted) sees the fresher entry kept and the deleted one gone after the merge.
- auto-session-name: the `agent_settled` handler no longer waits for the naming call. pi awaits every settled handler in load order and botsun-owner's `idle` comes after this one, so a turn that reset `attempted` (no title, or a failure below `MAX_AUTO_FAILURES`) held the phone's done signal for a whole model round trip — the same 5–13 s the canvas fix below takes out of its own handler, on every such turn. Tests: `test/auto-session-name.test.mjs` — the handler returns while the naming call is still in flight and the name still lands; the settle tests await a tick for it.
- agent-link: `/agent-link-reload` run with no reload dispatched (typed by hand, or sent by another extension) checks what a dispatched one did first: idle, no dialog open, no unsent text in the editor; otherwise it refuses with a notice and reloads nothing. A socket directory agent-link refuses to bind in (a shared `/tmp/cc-socks`, say) no longer stops it at startup: it says which directory and why, and binds in a per-user private one (`$TMPDIR/cc-socks-<uid>`) instead (Claude Code sends no delivery receipts there).
- provider-usage: a background poll keeps the shared fetch lock until its fetch (and the OAuth refresh in it) actually settles, not just until the 45 s wait ends, touching the lock's mtime every 15 s so no other pi takes it for a crashed one and refreshes the same sign-in alongside it (a provider that rotates refresh tokens could sign the user out). Past a 10-minute cap it stops touching the lock and no longer releases it. The test-only timer gauge is renamed from `liveBackgroundTimers` to `scheduledBackgroundTimers`, since it counts a fired one-shot timer until shutdown.
- agent-link: a registry entry (`~/.claude/sessions/<pid>.json`) is written to a temp file and renamed into place, so a peer listing, `ccSocksDir()` or `updatePeer`'s own read-modify-write no longer reads it half written (which dropped the peer from that listing, or the update). Tests: `packages/agent-link/test/reload.mjs` registers every test before its first await, so its extension tests can't be skipped and leave the file's process hanging on open sockets (CI jobs ran to the 6-hour timeout), the subagent sandbox test no longer depends on a Botsun checkout existing on the machine, bg-lifecycle sets file times in whole seconds so a 60 s job isn't read back as 59.999 s, and its prune test waits up to 5 s of real time for the prune rather than 200 event-loop turns.
- botsun-owner: a say that arrives while pi is compacting is held, not lost. pi refuses a prompt from the moment a compaction begins, but its `session_before_compact` handlers run in load order and another extension's can run for a minute first (extensions/compaction writes the whole summary inside its own), so this extension's `compacting` was still null when the phone's words came in: `inject` sent them straight to `pi.sendUserMessage`, pi refused, the refusal went only to the runner's error listeners, and the phone had already been told `delivered: "prompt"` (2026-11-10). A session that isn't idle with no turn running (Botsun's busy false) and no prompt sent in the last 10 s is now read as a compaction pi hasn't announced, and holds the words in order with everything else that waits; `inject`, the settled run's left steers, the voice helper's `deliver` and the words released after a Stop all check it before sending, and a send that still throws goes back to held. Held words are released by polling until pi takes them (idle or in a turn) and answer `delivered: "held"`, which Botsun passes through and its session voice already reads; past 10 minutes they go back to the phone's message box as a `returned` steer (`why: "withdrawn"`), never silently dropped. The old 60 s "send anyway" is gone.
- botsun-owner: a Stop or Close takes back only the phone's own steers. `takeQueued` removes only whole blank-line-separated blocks of the editor equal to a phone text, in queue order from the front, so a phone "ok" no longer cuts "looks ok to me" down to "los ok to me", and a delivered steer that `message_start` didn't match can't cut into Eric's draft. ### Added

- tmux-attention: `programStatus` reports only from pi's TUI. A print, json or rpc pi (a subagent child, a background run) inherits $TMUX but writes to a pipe, so its reports landed in that child's captured output and logs; such a pi now probes nothing and writes nothing. Test: `test/program-status.test.mjs` (each non-TUI mode stays quiet).
- ask, tmux-attention: pi's program status (OSC 7501) now reaches the terminal from every pi-boehsline dialog and from inside tmux. `ask`'s two custom pickers (single- and multi-select) passed no `blocked` option, so a terminal showed `working` while the tool waited on an answer; both now report `blocked`, `kind=question`, with the fixed title "Answer the agent's question" (a title, never the question text, tool arguments or model output), through the new `lib/blocked.ts` `withBlocked`, which types the option as the caller's own so a pi older than 1.5 still typechecks and simply ignores it. pi's own built-in `select`/`confirm`/`input` already report `blocked`, so menus opened by a slash command or shortcut (boehsline, footer, todo, stash, bg, prompt-history, watch, botsun-owner's icon picker, approval-guardian's settings) and the user-driven dialogs of color, cursor-agent, boehsline defaults, scheduler and `watch_items` keep pi's own report and are left alone. tmux answers no 7501 query and drops the OSC, so pi's reporter never sends one from a pane: the opt-in `tmux-attention` extension has a new `programStatus` setting (**off by default**, `"tmux-attention": { "programStatus": true }` in `boehsline.json`) that writes the same states through tmux's DCS passthrough (`ESC P tmux; … ESC \`, every inner ESC doubled), which tmux unwraps for the outer terminal (checked against tmux 3.8 in a real session: a raw report from a pane never reached the client, with `allow-passthrough` off or `all`, and the wrapped one arrived as the very OSC pi wrote). It probes `tmux show-options -gv allow-passthrough` once at session start and writes nothing unless it is `on` or `all`, writes nothing at all when `PI_PROGRAM_STATUS` is set (pi reports for itself then, and two reporters would double every state), dedupes repeats, and sends `clear` on exit as pi does. One `ActivityTracker`, extracted from canvas's page mirror into `lib/program-status.ts` and re-exported there, drives both the passthrough report and the window flag (`@special_activity` on a dialog, off when it closes), so the tmux window and the terminal can't disagree. The encoder follows pi's own rules and a test pins it to `pi-tui`'s field for field. Tests: `test/program-status.test.mjs` (the encoder against pi-tui, ESC doubling, only `on`/`all`, `withBlocked`, and the state stream: `idle` → `working` → `done` → `blocked` with the dialog title → `error` from a failed turn, nothing written when passthrough is off/unset or the setting is closed, nothing when `PI_PROGRAM_STATUS` is set, and the window flag tracking the same states), `test/ask.test.mjs` (both pickers pass `blocked`, `kind=question`, without the question text).
- scheduler, canvas, botsun-owner: a running job or scheduled run can be tailed and stopped from Botsun's info sheet. A durable run now writes its output (stdout and stderr, as it arrives) to `~/.pi/agent/scheduler/runs/<id>/<runId>.log` (mode 0600 in a 0700 folder, capped at 5 MB; the newest 10 kept per task, and they go with `remove`/`prune`); `runId` is the claim's `runningSince`, which the run history now records as its `runId` too. Bash is best effort: a deny root written out in any word (`~`, `$HOME`, `${HOME}`, `$USER`, `~user`, the absolute path, a brace or glob form that reaches it, case-insensitive on macOS), a word that resolves into one from the cwd or a `cd` target (symlinks followed), a home-relative root in code (`'.ssh'` in a Python/Ruby/Node/shell one-liner or interpreter heredoc), what runs inside `$(…)` and backticks (a finder's output read by the outer command counts as a recursive read: `cat $(find ~ -name id_rsa)`), `cd` forms (bare `cd`, `cd -P`, `cd --`) for later relative words, earlier `VAR=` assignments, `$'…'` ANSI-C quoting, line continuations, recursive readers with no path argument (`rg -uu KEY` in home; not when reading a pipe), and recursive readers (rg, grep -r, tar, zip, rsync, cp -r, find -exec/xargs) on a folder holding a root. Heredoc bodies are text, never resolved as paths or globs; a body written by `cat`/`tee`/`git`/`gh` is data and is not checked (running that file later is a known gap), unless its line holds an expansion the lexer can't be sure of (`$(`, backticks, `${`, `$[`, `((`, `$'`, `case`), in which case it is scanned as shell; the common `"$(cat <<'EOF'` commit/PR body shape stays data. Heredoc operators are found with a quote- and expansion-aware lexer, a body is checked in the folder its own command runs in, and an unquoted body's `$(…)` is checked whoever reads it. `deny.paths` and `deny.commands` (case-sensitive regular expressions) in `approval-guardian.json`: the global file's lists replace the defaults (an empty `deny.paths` is warned about), a trusted project may add paths only. The guardian's own config files (global and project `approval-guardian.json`) can't be written or edited by any tool call, so a reviewer-approved write can't empty the list. `~/.local/share/pi-memory` is not on the list (the memory tools read it, and its writes are scanned). Secret CLIs are not denied but reviewed as a private-data read (the reviewer gets no tools and needs the user's explicit authorization), even with bash review off: `op read|item|inject|run|signin|document|vault`, directly, in a pipeline, in `$(…)`, `sh -c '…'` or an interpreter heredoc, since an unlocked 1Password CLI hands secrets out without a prompt for minutes. Also reviewed that way by default: a keychain item's password (`security find-generic-password`/`find-internet-password` with `-w`/`-g`; the credentials skill reads API keys that way, so it is not denied; add `KEYCHAIN_PASSWORD_RULE` to `deny.commands` to refuse it), `gh auth token`, `kubectl config view --raw`, `git credential fill|get`, `aws configure export-credentials|get`, `docker-credential-* get`. `secretCommands.patterns` / `secretCommands.allow` (regular expressions per simple command; default allow: `fnox`) configure it, in the global file only.

- failover: a model that hits its usage limit doesn't end the turn any more. At `agent_settled` it recognises the non-retryable quota/usage-limit errors stock pi refuses to retry (GoUsageLimitError, insufficient_quota, "usage limit", Copilot "premium requests", "exceeded/reached … limit|quota", account billing limits, plan 1308 — not a bare 429, a throttle, a network error, a context overflow, or an abort) and moves to the next usable model in `failover.chain` (`provider/model`, preferred first), then sends "continue". Models with no auth, already tried, or with a window the shared `usage-cache.json` shows used up are skipped; one line says who hit what and where work went. The reset time comes from the cache (`resetMs`/`resetDate`/`windows[].resets_at`, variant keys included), else a 30-minute backoff, and a timer switches back to the preferred model at that point and sends "continue" only when the work never resumed — the branch still ends on the limit entry, nothing is queued, the editor is empty, the model is still the one failover switched to, and a wake has not already resumed this work once. A switch-back that lands mid-run is deferred to the next idle point (and dropped if Eric aborts), and settings are re-read only when `boehsline.json`'s mtime changes. `failover.enabled` (default on with a chain) and `failover.maxSwitches` (default 3 per task) bound it: an exhausted chain, a spent budget, or two failed `setModel` attempts stop once (with no timer left armed) and ask for Eric through quiet's `notify_user` path (`ctx.ui.notify` without quiet). A wake does not reset that budget, and every promise on the timer path is caught. A model that hit its limit stays skipped until its reset even in the next task, Anthropic's per-family entry (`claude-window:opus`) is read on its own so a full Opus week does not take Sonnet with it, a wake that finds pi busy (idle compaction) retries every 60 s, and the line says `retry ~HH:MM` when the wait is only the backoff guess. Never acts on an abort or in print/json mode, and timers are cleared on session shutdown.
- quiet: background work stays quiet. A run Eric started (typed, RPC, or relayed from Botsun over `quiet:mine`) keeps its normal attention; every other run — a bg job finishing, a subagent result, an agent-link message, a `codemode_bg` result, a scheduler or Botsun trigger, or a `pi.sendMessage(..., { triggerTurn: true })` run — is quiet unless the agent calls `notify_user` or a cheap classifier (`opencode-go/deepseek-v4.1-flash`, configurable) decides he is needed. Quiet runs get a one-line system-prompt hint, append a digest line to `~/.local/state/pi-quiet/YYYY-MM-DD.log`, and share `quiet:run` / `quiet:attention` over `pi.events` plus `globalThis[Symbol.for("pi-boehsline.quiet")]`. `quietMode: "off"` treats every run as Eric's. tmux-attention skips marking the window on a quiet settle and follows `quiet:attention`; botsun-owner sends `busy` with `quiet`, repeats `busy` when a run flips to Eric's, sends an `attention` line, and marks every `sendUser` as Eric's.

- cursor-agent: a finished run (success, failure or stop) records what it changed, for Botsun's Show work. The tool result and a background completion message carry `details.diff` (unified diff, capped at 256 KB on a file boundary), `details.diffStats` (`{files, insertions, deletions, truncated}`) and `details.diffPath` (the full masked diff, `0600` in a `0700` dir under `~/.local/state/pi-cursor`, named `<run id>-<random>.diff`, pruned to 14 days and the newest 200). Masking covers named secrets, bare tokens with well-known prefixes (`ghp_`, `github_pat_`, `AKIA`, `sk-`, `xox*-`, `glpat-` …), letter-only `sk-`/`pk-` keys of 20 or more characters, URL credentials and private key blocks. Tokens in an omitted file's path are masked too. Binary files, sensitive files (`.env*`, keys, `id_*`, `.npmrc`, `.netrc`, `credentials*.json` …, including a trailing slash or backslash) and large files (over 1 MB changed, or untracked over 5 MB, never staged) are one line naming them. Rename detection is forced (`diff.renames=true` and `-M1%`), so renaming a sensitive file, even a small one that was also edited, cannot show its body as an add. Tracked changes are against the run's base, measured over the whole repo even from a subdirectory; untracked, non-ignored files are included. Snapshots seed a scratch index from the real one. A failed or timed-out snapshot gives no diff, not a partial one. After a stop, each git call gets 5 s and only files the base had are re-read. A Cursor child's transcript ends with a `custom` / `cursor_diff` entry (`{diff, diffStats, diffPath?}`). An edit event's patch or `old_string` / `new_string` (never whole-file content; nothing when any path key or patch header names a sensitive file) stays on that step's tool-call arguments. A background run's log numbers its steps (`→ #3 …`), so its sidecar edits attach by step id. Only the cursor runner marks a job for a sidecar (an unexported set in runner.ts; `details: true` on a plain `bg:start` does not, and a forged stack cannot). That flag is not saved. At spawn and on completion the sidecar is set or read only when the job command's argv[1] realpaths to this package's runner.ts. cursor-agent is spawned without any `PI_BG_*` variable. The sidecar is opened without following a symlink and reduced again on read: per-edit old/new bodies are dropped, and only a reduced diff is kept. `diffPath` is kept only when the state dir is not a symlink, the file's real directory is that dir, and the file is a regular `0600` file with one link, owned by us (the dir `0700`); the path returned is the real path, and its bytes are reduced before the phone is told. `---` / `+++` headers count with or without an `a/` or `b/` prefix (`/dev/null` does not). `uri` and `fileUri` are path keys, and a `file://` value is decoded. Step summaries are secret-masked, including in a background job's log tail. Sidecar temp files use only a random name opened `O_EXCL|O_NOFOLLOW`.
- bg: background jobs survive `/reload`, a pi restart and resuming the session. On reload the old instance hands its job table to the new one (same session id). Each job runs under a small `/bin/sh` wrapper that writes its exit status to `<log>.exit`, and each persisted session's jobs are kept in `~/.local/state/pi-bg/<sessionId>.json` (0700/0600, metadata only, `PI_BG_STATE_DIR`). Background jobs refuse a log directory others can write to.
- memory (opt-in): durable facts shared by every pi session on the host. One markdown file per fact under `memory.root` (default `~/.local/share/pi-memory`), in `global/` or `projects/<host>/<org>/<repo>/` (the slug from the git origin, so worktrees share it), committed to a local git repo that refuses to commit once it has a remote and runs no hooks, filters or diff drivers. The root must be new, empty or already a pi-memory root (a `.pi-memory` marker), so a mistyped root can't take over a project. Tools `remember`, `memory_search`, `forget`, `memory_update`; `/memory` (status, search, add, edit, forget, restore, pin, context, qmd setup); `bin/pi-memory` for the shell. Every write goes through a scanner (secrets, personal identifiers, prompt-injection text, `scanner.extraPatterns`) that refuses and names the category without echoing the text, and an 80% word-overlap duplicate check. The scanner also reads the text folded (full-width, accents, invisible characters, Cyrillic and Greek lookalikes, line breaks). A session's first prompt gets a frozen `memory` section (pins, then this repo's and global facts within `inject.startChars` / `inject.startMax`); facts and pins are scanned again there and in search, so a hand-edited file the scanner refuses is left out. qmd is optional: `pi-memory qmd setup` registers the `memory` collection, and `memory_search` merges `qmd query` hits with the built-in search, falling back on any error.
- subagent, botsun-owner: a pi subagent now says how full its conversation is. Its usage carries `context`, the last turn's input plus cache reads and writes plus output (never the run's totals), and the list carries `window`, the context window of the model it runs (lib/children.ts's `modelWindow`: an exact `provider/id`, or a bare id only when exactly one model has it, a `:thinking` suffix ignored; a background pi child's log banner now ends `… · 1.2k ctx · $0.0038`). botsun-owner sends both as plain integers per subagent, inside the existing 56 KB line, leaving each out when it doesn't know it (a Cursor run, a model pi can't resolve, a background child whose log predates the banner, a turn that reported no usage). Nothing else on the line changed.
- subagent, botsun-owner: each subagent keeps its conversation in a session file's shape (the task as the user message, its text, tool calls with masked arguments and short results, then its final reply; at most 400 entries or 512 KB, the oldest work dropped first, the task and the final reply kept), for 10 minutes after it ends like the list. Foreground pi children fill it from their JSON events; background children and Cursor runs from their logs. botsun-owner serves it a page at a time (`child_transcript`, unsigned, this session's children only; feature `subagent_chats`), and the phone opens it as a read-only chat.
- botsun-owner: Botsun can rename a session. A `{"type":"name"}` line from Botsun (the phone's info sheet, signed there) sets pi's session name for the session pi is in, through `setSessionName` only, and a features line says the new name back at once. `name` is in the features, so Botsun uses the line instead of sending `/name`. A name with control characters, line separators or direction marks is refused (the phone's `/name` too). A name set through pi from Botsun is what every line says, over an older agent-link name.
- botsun-owner: the phone's info sheet can Reload or Restart a session. `reload` and `restart` requests are signed like `close` (v2 or newer, decision key, each over its own decision and payload: `reload` / `restart`) and refused while a turn, a compaction or a prompt on its way in runs, or a dialog is open (nonce spent). Reload is `/reload`'s own: pi offers reload only on a command's context, so the verified request runs `/botsun-reload` with a one-time token, and the command reloads only with that token.
