# Changelog

## Unreleased

### Added

- canvas: markdown keeps `botsun://` links. `render.mjs`'s `MD_CLEAN` passes DOMPurify an `ALLOWED_URI_REGEXP`: DOMPurify's own default list plus `botsun:`, so Botsun's synced copy (`botsun render sync`) keeps session links in page-drawn messages instead of dropping them to plain text. `javascript:`, `data:` and the rest stay stripped.
- botsun-owner: `/icon` with no arguments draws the looks. In Ghostty, Kitty or WezTerm (in tmux too, by passthrough), the picker is a grid of each look's idle frame beside its name, blinking as the footer avatar does (each on its own clock, a Kitty animation of the strip's blink frames), in the color it would keep, then the chosen look in every color; type to filter, arrows to move, Enter to pick. Frames are cut straight from Botsun's exported strips (`~/.local/share/botsun/icons/<look>/<color>.png`, or `BOTSUN_ICONS_DIR`) without ImageMagick (only the frame's columns are unfiltered), halved to 64 px, cached for the next `/icon`, sent as zlib RGBA through Kitty Unicode placeholders, and deleted when the picker closes. Any other terminal, no strips, or `BOTSUN_ICON_IMAGES=0` gets the plain list as before.
- botsun-owner: a `/icon` pick shows at once. The session's look is set and announced on the pi event `botsun:icon` (`{look, color}`) when the pick is made, before Botsun answers; a refusal puts the old look back, and Botsun's icons lines and answers announce too when they change it. A footer avatar listening there redraws without waiting for its poll. A pick made in a new session, before pi has written its file (Botsun answered `this session's file doesn't name it yet`), is drawn at once and held, says `(Botsun saves it after your first message)`, and goes once the first message has put the file there; an auto-name suggestion doesn't cover it.
- memory (opt-in): notes get a review. Two optional front matter fields: `expires: YYYY-MM-DD` (the fact is in force through that day, local time) and `verified: { at, status, by, evidence, of }` (`confirmed`/`contradicted`/`unverifiable`, plus the session id(s) that say why). `remember` and `memory_update` take an optional `expires` and refuse a bad or past day; the remember tool says to set one for a limited-time fact ("this weekend", "until the release"). New tool `memory_verify {id, status, evidence}` records a check (evidence scanned whole and only then cut at 300 characters, commit `verify <id> <status>`) without touching `updated`, and records the fact's version as `verified.of` (a short hash of its text and expiry) so an edit in the same second as the check still counts as "changed since verification". `pi-memory verify` needs both `--status` and `--evidence`. `restore` clears `expires`, so a restored fact doesn't come back active but expired. An expired fact is never injected or returned by `memory_search`, and `pi-memory expire` (or the review's check) archives it through the normal path, one `expire <id>` commit each, restorable for 30 days. `pi-memory review-check [--days 14] [--json]` archives expired facts and prints what is due — never verified, verified more than `--days` ago, updated since its last verification, or contradicted — exiting 0 when something is due, 3 when nothing is and 1 on an error, so a scheduled run stops early without confusing "nothing to do" with "it broke". The CLI gains `verify`, `expire`, `review-check` and `--expires` on `add`/`edit`; `/memory` and `pi-memory status` count facts expiring within 7 days and facts never verified. `extensions/opt-in/memory/review-prompt.md` is the nightly review itself (review-check, then `qmd search -c sessions` / `qmd query -c sessions` at most ~4 times per fact, verify, fix or forget what changed, add an expiry to a time-bound fact, one-line report), with the one-time `pi-scheduler add --name memory-review … daily 03:30 :: …` command documented in the README. Old memory files parse unchanged.
- approval-guardian: a session that ended with the guardian bypassed gets `/approval-guardian bypass` typed into its editor when it is resumed (or restarted into), with a warning notice; the bypass itself stays off until the user presses Enter. Each bypass change is recorded as a `approval-guardian-bypass-state` session entry. An editor already holding text is left alone, and nothing is offered on `/new`, `/fork`, `/reload` or outside the TUI. `pi-restart-all` empties the editor line (Ctrl+E Ctrl+U) before typing a command, so the restore it types does not double up with the offer.
- failover: a model that hits its usage limit doesn't end the turn any more. At `agent_settled` it recognises the non-retryable quota/usage-limit errors stock pi refuses to retry (GoUsageLimitError, insufficient_quota, "usage limit", Copilot "premium requests", "exceeded/reached … limit|quota", account billing limits, plan 1308 — not a bare 429, a throttle, a network error, a context overflow, or an abort) and moves to the next usable model in `failover.chain` (`provider/model`, preferred first), then sends "continue". Models with no auth, already tried, or with a window the shared `usage-cache.json` shows used up are skipped; one line says who hit what and where work went. The reset time comes from the cache (`resetMs`/`resetDate`/`windows[].resets_at`, variant keys included), else a 30-minute backoff, and a timer switches back to the preferred model at that point and sends "continue" only when the work never resumed — the branch still ends on the limit entry, nothing is queued, the editor is empty, the model is still the one failover switched to, and a wake has not already resumed this work once. A switch-back that lands mid-run is deferred to the next idle point (and dropped if Eric aborts), and settings are re-read only when `boehsline.json`'s mtime changes. `failover.enabled` (default on with a chain) and `failover.maxSwitches` (default 3 per task) bound it: an exhausted chain, a spent budget, or two failed `setModel` attempts stop once (with no timer left armed) and ask for Eric through quiet's `notify_user` path (`ctx.ui.notify` without quiet). A wake does not reset that budget, and every promise on the timer path is caught. A model that hit its limit stays skipped until its reset even in the next task, Anthropic's per-family entry (`claude-window:opus`) is read on its own so a full Opus week does not take Sonnet with it, a wake that finds pi busy (idle compaction) retries every 60 s, and the line says `retry ~HH:MM` when the wait is only the backoff guess. Never acts on an abort or in print/json mode, and timers are cleared on session shutdown.
- quiet: background work stays quiet. A run Eric started (typed, RPC, or relayed from Botsun over `quiet:mine`) keeps its normal attention; every other run — a bg job finishing, a subagent result, an agent-link message, a `codemode_bg` result, a scheduler or Botsun trigger, or a `pi.sendMessage(..., { triggerTurn: true })` run — is quiet unless the agent calls `notify_user` or a cheap classifier (`opencode-go/deepseek-v4.1-flash`, configurable) decides he is needed. Quiet runs get a one-line system-prompt hint, append a digest line to `~/.local/state/pi-quiet/YYYY-MM-DD.log`, and share `quiet:run` / `quiet:attention` over `pi.events` plus `globalThis[Symbol.for("pi-boehsline.quiet")]`. `quietMode: "off"` treats every run as Eric's. tmux-attention skips marking the window on a quiet settle and follows `quiet:attention`; botsun-owner sends `busy` with `quiet`, repeats `busy` when a run flips to Eric's, sends an `attention` line, and marks every `sendUser` as Eric's.
- cd: `/cd <dir>` continues the conversation in another directory. It expands `~`, resolves a relative path against the session's cwd, waits for idle, forks the session file into the target with `SessionManager.forkFrom` (the source stays put), and runs `pi-restart-all --only <pane> --session <new file> --cd <dir>` so the same tmux pane relaunches there with the guardian's bypass restored. Outside tmux, or without the restart extension's record, it says `/cd needs pi running in tmux` and changes nothing. `pi-restart-all` gains `--session FILE` and `--cd DIR` (with `--only`), and its `--dry-run` prints the `cd -- … && pi --session …` it would type.
- providers: two former pi-fork patches as `registerProvider()` overrides on mainline pi. `disabledProviders` (a list of provider ids in `~/.pi/agent/settings.json`) re-registers each listed built-in with no available models, so it leaves `/model`, cycling, startup selection and subagent model lists while explicit lookups still resolve. GitHub Copilot's Anthropic Messages bodies are sent zstd-compressed (Content-Encoding: zstd, level 3) through `StreamOptions.fetch`; a 400 or 415 is retried once uncompressed, and when that is accepted the base URL stays uncompressed until pi exits.
- bg: `codemode_bg` runs a codemode script detached and delivers its result as one message, so a long workflow (coop workers, reviews, fix rounds) does not hold the turn. Mainline pi only: it builds its own codemode definition with the exported `createCodemodeExtension()`, since `codemode` itself is `model-only`.
- botsun-owner: `/icon [look] [color]` sets this session's icon on Botsun's Home, the shapes, character sets and palette the phone's icon sheet offers. No arguments picks a look, then a color (or "keep color"). `/icon auto` or `/icon off` clears it. It needs Botsun (`/icon needs Botsun` otherwise). Botsun sends the catalog and the current look, and checks every set; a bad look or color is unchanged and the answer says why.
- auto-session-name, botsun-owner: a new session also gets a look and a color that fit it ("Cactus Winter Keeper" in `nature.cactus`, green). botsun-owner hands auto-session-name the catalog Botsun sent, plus what each look draws from Botsun's `looks` pages (behind the `look_notes` feature, pages under the line limit, published on the last), and auto-session-name asks the same naming call for JSON: the name with a look and a color, each checked against the catalog. The suggestion goes back to botsun-owner, which sends it as an icon line with `if_unset` only while no look is saved here (nothing from `/icon`, nothing from the phone's sheet, no pick in flight), so a suggestion never covers a choice. No Botsun, no catalog, or a bad reply: the name still lands, with no icon line. Botsun keeps a suggestion only while nothing is saved there either.
- cursor-agent: a finished run (success, failure or stop) records what it changed, for Botsun's Show work. The tool result and a background completion message carry `details.diff` (unified diff, capped at 256 KB on a file boundary), `details.diffStats` (`{files, insertions, deletions, truncated}`) and `details.diffPath` (the full masked diff, `0600` in a `0700` dir under `~/.local/state/pi-cursor`, named `<run id>-<random>.diff`, pruned to 14 days and the newest 200). Masking covers named secrets, bare tokens with well-known prefixes (`ghp_`, `github_pat_`, `AKIA`, `sk-`, `xox*-`, `glpat-` …), letter-only `sk-`/`pk-` keys of 20 or more characters, URL credentials and private key blocks. Tokens in an omitted file's path are masked too. Binary files, sensitive files (`.env*`, keys, `id_*`, `.npmrc`, `.netrc`, `credentials*.json` …, including a trailing slash or backslash) and large files (over 1 MB changed, or untracked over 5 MB, never staged) are one line naming them. Rename detection is forced (`diff.renames=true` and `-M1%`), so renaming a sensitive file, even a small one that was also edited, cannot show its body as an add. Tracked changes are against the run's base, measured over the whole repo even from a subdirectory; untracked, non-ignored files are included. Snapshots seed a scratch index from the real one. A failed or timed-out snapshot gives no diff, not a partial one. After a stop, each git call gets 5 s and only files the base had are re-read. A Cursor child's transcript ends with a `custom` / `cursor_diff` entry (`{diff, diffStats, diffPath?}`). An edit event's patch or `old_string` / `new_string` (never whole-file content; nothing when any path key or patch header names a sensitive file) stays on that step's tool-call arguments. A background run's log numbers its steps (`→ #3 …`), so its sidecar edits attach by step id. Only the cursor runner marks a job for a sidecar (an unexported set in runner.ts; `details: true` on a plain `bg:start` does not, and a forged stack cannot). That flag is not saved. At spawn and on completion the sidecar is set or read only when the job command's argv[1] realpaths to this package's runner.ts. cursor-agent is spawned without any `PI_BG_*` variable. The sidecar is opened without following a symlink and reduced again on read: per-edit old/new bodies are dropped, and only a reduced diff is kept. `diffPath` is kept only when the state dir is not a symlink, the file's real directory is that dir, and the file is a regular `0600` file with one link, owned by us (the dir `0700`); the path returned is the real path, and its bytes are reduced before the phone is told. `---` / `+++` headers count with or without an `a/` or `b/` prefix (`/dev/null` does not). `uri` and `fileUri` are path keys, and a `file://` value is decoded. Step summaries are secret-masked, including in a background job's log tail. Sidecar temp files use only a random name opened `O_EXCL|O_NOFOLLOW`.
- bg: background jobs survive `/reload`, a pi restart and resuming the session. On reload the old instance hands its job table to the new one (same session id). Each job runs under a small `/bin/sh` wrapper that writes its exit status to `<log>.exit`, and each persisted session's jobs are kept in `~/.local/state/pi-bg/<sessionId>.json` (0700/0600, metadata only, `PI_BG_STATE_DIR`). On resume a job is re-adopted only when its pid, its start time and the wrapper's arguments all match; jobs that ended meanwhile are reported once ("while the session was closed"); a reused pid is never signalled, and an unverifiable one is neither adopted nor reported. Background jobs refuse a log directory others can write to.
- memory (opt-in): durable facts shared by every pi session on the host. One markdown file per fact under `memory.root` (default `~/.local/share/pi-memory`), in `global/` or `projects/<host>/<org>/<repo>/` (the slug from the git origin, so worktrees share it), committed to a local git repo that refuses to commit once it has a remote and runs no hooks, filters or diff drivers. The root must be new, empty or already a pi-memory root (a `.pi-memory` marker), so a mistyped root can't take over a project. Tools `remember`, `memory_search`, `forget`, `memory_update`; `/memory` (status, search, add, edit, forget, restore, pin, context, qmd setup); `bin/pi-memory` for the shell. Every write goes through a scanner (secrets, personal identifiers, prompt-injection text, `scanner.extraPatterns`) that refuses and names the category without echoing the text, and an 80% word-overlap duplicate check. The scanner also reads the text folded (full-width, accents, invisible characters, Cyrillic and Greek lookalikes, line breaks). A session's first prompt gets a frozen `memory` section (pins, then this repo's and global facts within `inject.startChars` / `inject.startMax`); facts and pins are scanned again there and in search, so a hand-edited file the scanner refuses is left out. qmd is optional: `pi-memory qmd setup` registers the `memory` collection, and `memory_search` merges `qmd query` hits with the built-in search, falling back on any error.
- subagent, botsun-owner: a pi subagent now says how full its conversation is. Its usage carries `context`, the last turn's input plus cache reads and writes plus output (never the run's totals), and the list carries `window`, the context window of the model it runs (lib/children.ts's `modelWindow`: an exact `provider/id`, or a bare id only when exactly one model has it, a `:thinking` suffix ignored; a background pi child's log banner now ends `… · 1.2k ctx · $0.0038`). botsun-owner sends both as plain integers per subagent, inside the existing 56 KB line, leaving each out when it doesn't know it (a Cursor run, a model pi can't resolve, a background child whose log predates the banner, a turn that reported no usage). Nothing else on the line changed.
- subagent, botsun-owner: each subagent keeps its conversation in a session file's shape (the task as the user message, its text, tool calls with masked arguments and short results, then its final reply; at most 400 entries or 512 KB, the oldest work dropped first, the task and the final reply kept), for 10 minutes after it ends like the list. Foreground pi children fill it from their JSON events; background children and Cursor runs from their logs. botsun-owner serves it a page at a time (`child_transcript`, unsigned, this session's children only; feature `subagent_chats`), and the phone opens it as a read-only chat.
- botsun-owner: Botsun can rename a session. A `{"type":"name"}` line from Botsun (the phone's info sheet, signed there) sets pi's session name for the session pi is in, through `setSessionName` only, and a features line says the new name back at once. `name` is in the features, so Botsun uses the line instead of sending `/name`. A name with control characters, line separators or direction marks is refused (the phone's `/name` too). A name set through pi from Botsun is what every line says, over an older agent-link name.
- botsun-owner: the phone's info sheet can Reload or Restart a session. `reload` and `restart` requests are signed like `close` (v2 or newer, decision key, each over its own decision and payload: `reload` / `restart`) and refused while a turn, a compaction or a prompt on its way in runs, or a dialog is open (nonce spent). Reload is `/reload`'s own: pi offers reload only on a command's context, so the verified request runs `/botsun-reload` with a one-time token, and the command reloads only with that token. Restart runs `pi-restart-all --only <pane>`, which restarts this pi in its tmux pane and resumes the session; it's offered only when the script would act on it: in tmux, with the restart extension's record. Both reply `{ok}` first and act after the reply, checking again that nothing started. Features `reload` and `restart` (the latter only while possible, re-sent when that changes at a session start).

### Changed

- botsun-owner: the phone's model picker gets the whole catalogue (up to 1,000 models, scoped ones first) instead of an arbitrary first 120, and each model says whether it is one of the session's scoped models (`enabledModels` / `--models`). The list goes on `models` lines after hello, and Botsun negotiates the shape: a host that lists `model_pages` in its features line gets pages of at most 48 KB of JSON (measured, not counted, since the field caps are characters), the first saying `first: true` and the last `last: true`, which is when the host publishes the list. A host from before that gets one page, scoped models first, since it replaces its list on every `models` line. hello keeps a first page of its own, under 24 KB. A host that takes pages gets the catalogue once per hello (from its features line), not twice.
- auto-session-name: names are Title Case with spaces, read like a character on the job (the thing being worked on plus one role noun: **Chicken Door Alert Tamer**, **Flaky CI Wrangler**), and may run to 30 characters. Acronyms and brand casing (CI, GitHub) are kept; a kebab-case reply is still split and title-cased.
- footer: a session name saved with outer quotes (`/name "Foo Bar"` before the pi fork stripped them) shows without them.
- agent-link: a spaced session name answers to its lowercase, hyphenated handle and its prefixes (`@chicken-door` for "Chicken Door Tamer"), in @mentions, autocomplete, and `to`. Autocomplete inserts the handle, since a space ends an @mention.
- canvas: findings are gone. The `finding` kind, the guideline asking agents to record them, Haiku's findings field and the Findings card are removed; nothing read them after the fact. Old `findings.md` files are left on disk and ignored.
- cursor-agent: the footer **Cursor spend** chip shows billing-cycle Cursor spend on the border row (matching `pi-usage`), pace-colored over the cycle, instead of a `cursor` line on the status row. Three modes, cycled by a click: mini `⬡ $113` (default), compact `⬡ $113/$200`, and detailed `⬡ $113.28/$200 (57%)` with a dim `· +$… here` for this session's runs.

### Fixed

- memory: the session's memory block and every memory listing keep path-like placeholders such as `~/Code/<host>/<org>/<repo>`, `<pid>.json` and `<YYYY-MM-DD>` readable only when the name is in a closed placeholders allowlist; everything else, including bare `<important>`, `<note>`, `<override>`, wrapper tags (memory, pins, untrusted, skills, project_context, system_reminder), prompt tags and HTML tags, is still defused through the same `oneLine`.
- cursor-agent: `runCursor` without an `onEvent` callback never read cursor-agent's output (`onEvent?.(run, run.feed(…))` skipped the feed), so the answer and steps were empty.
- subagent: an answer over the 50 KB cap keeps its `[N bytes over cap omitted]` note; the cut used to remove the note along with the excess.
- image-prune: saved images (`~/.pi/agent/tmp/image-prune/`) are owner-only (files 0600, folder 0700) and no longer kept forever: each session start deletes ones older than 7 days and keeps at most the newest 200.
- auto-bundle: the detached rebuild gets the lock, log, script path and version as positional arguments instead of `JSON.stringify` spliced into shell text, so a `$`, backtick or quote in a path or version is never run.
- stash: a session's entry is deleted from the shared store when its stack empties, and creating one drops other sessions' empty ones, so a long-lived process no longer keeps an entry per session it saw.
- provider-usage: an idle Claude 5h window no longer looks like a missing one. Anthropic returns `resets_at: null` while `five_hour` has no active usage, and the chip needs a reset to show elapsed/total, so the window was dropped silently; the code now says why.
- provider-usage: the opencode-go and codex shared-cache entries carry `windows` (label, percent, `resets_at`) and the soonest `resetMs` from the meters already fetched, so other extensions can tell a provider is used up and when its window reopens from `usage-cache.json` alone.

- compaction: a model whose thinking map has no `off` level (Copilot Sonnet 5.5) gets low-effort adaptive thinking instead of `thinking: disabled`, which the API rejects. Opus 5.5 is unchanged. Models with `off: null` other than Opus 5.5 still fall back to pi.
- compaction: an update may grow the summary by 4,000 characters, and the checkpoint is kept at or under 32,000. The old instruction said to preserve every earlier bullet, so a long session's summary grew until the next compaction had to re-emit it and could hit the output limit. The split-turn block and file lists are kept; the oldest Done bullets are what get dropped.

### Added

- cursor-agent: `force` passes cursor-agent `--force`, for shell commands with `network: true` (outside the sandbox every command needs approval, and print mode can't give it). Never implied by `network`. Also on the subagent's cursor runner, per call or as `force: true` in a user-scope agent file (repo agent files can't set it, like `network`). Refused steps now show as refused instead of succeeded, and a run is stopped after 3 refusals with an error naming the fix.
- cursor-agent: background runs and `cursor` subagent runs refresh the shared usage cache (`cursor-usage`) when they end, like foreground runs, so `pi-usage` shows their spend.
- subagent: a built-in `cursor` agent (or an agent file with `runner: cursor`) runs Cursor's agent CLI instead of a pi child, through cursor-agent's own run.ts and runner.ts. Foreground tasks return the same result block as a background cursor run (answer, model, duration, charge in dollars, worktree, exit code, error) and put those facts in `details.results[i].cursor`. `background: true` starts the cursor runner as a bg job, so the completion message carries that block. Parallel `tasks` can mix `scout`, `worker` and `cursor`. Each cursor task gets its own git worktree by default; `model`, `cursorMode` and `worktree` override per call or per task (a per-task `model` also applies to pi children). Without cursor-agent enabled or `cursor-agent` installed, only that task fails, with a message saying which. The tool's description says cursor tasks must never carry PII, PHI or secrets, and adds cursor-agent's configured `note` and `rules`.
- cursor-agent: runner.ts exports `startJob`, `runAndCharge` and `resultBlock`, and run.ts exports `binFound`, so the cursor tool and the subagent tool start and report runs the same way.
- cursor-agent: `background: true` runs Cursor as a bg job (runner.ts) and returns at once. `/bg` shows each step live, and a message brings back the answer, the charge, the worktree and the exit code when it finishes. The foreground and background paths share run.ts.
- cursor-agent: Cursor's billing-cycle spend goes into pi's shared `usage-cache.json` as `cursor-usage` after each `cursor` run and on `/cursor-usage`, so `pi-usage` lists it with the other providers.
- cursor-agent: `/cursor-worktrees` lists the `pi-*` worktrees the tool left behind, with their changed files, and applies each to its repo (uncommitted) or removes it.
- cursor-agent: `worktree` (and `worktreeBase`) runs each call in its own git worktree and branch, so parallel calls can't collide; the result names the path, branch and changed files. The tool also declares an `outputSchema`, so codemode scripts get `{answer, steps, chargedCents, tokens, sessionId, …}` instead of text.
- cursor-agent (opt-in): a `cursor` tool that delegates a task to Cursor's agent CLI (`cursor-agent -p`, sandboxed by default), streams its steps, returns its final answer, and reports the run's real charged cost from Cursor's dashboard API (macOS Keychain login). A footer chip keeps the session's Cursor spend; `/cursor-usage` shows the billing cycle against the per-user limit. Neutral by default: a default model, blocked models, a description note and extra prompt rules come from Boehsline config (so a work package can supply them) or `PI_CURSOR_*` env vars.
- op-broker (opt-in): agents read 1Password through an approval card in the session (Allow once, 1 hour or 8 hours per item), and one shared daemon holds a single 1Password CLI authorization for every session, so it's one Touch ID per 12 hours, not one per command. An `op` shim takes `op read`, `op item get --otp` and `op item get --fields --reveal`, and everything else runs the real `op`. The card is a keyboard yes; the README states the risk.
- botsun-owner (opt-in): puts each interactive pi session on Eric's phone through Botsun. It reports state over `~/.local/state/botsun/owner.sock` (`$BOTSUN_OWNER_SOCK`) for the Sessions list (`hello`, `busy`/`idle`, `prompt`/`prompt_end`, `stream`, `model`, `ask`, `commands`, `models`, `session`, `bye`), and takes signed input on its own `owner/<pid>.sock`: replies with photos and files, call audio, `ask` answers, slash commands (`/compact`, `/model`, `/thinking`, `/name`, extension commands, templates, skills). The session verifies every signature itself against `owner-keys.json`. It never creates the shared socket, retries quietly with backoff, and stays off in subagent children and print, JSON and RPC sessions.
- botsun-owner: more of the session on the phone. The message stash (`stash` line; signed `push`/`take`/`drop`), context use (`context`), the footer's chips (`footer`, with `footer_tap` flipping a display chip and answering with the new row), compactions (`compacting`, holding the phone's words until pi takes prompts again), and the guardian's bypass (`bypass`; a signed `/bypass on|off`). `/reload` re-sends commands, models, context and stash.
- botsun-owner: a call's words can wait for a voice helper. `say_audio` with `hold: true` verifies them and holds them; `release {ids, mode}` puts them in as a follow-up, a steer, or an interrupt that aborts the run only when Eric's own words say stop; `drop` and `call_end` forget them. A `held` line carries ids and sizes only.
- botsun-owner: `ask` answered by voice. `say_audio` can carry `proposal_sha256` (signed with the audio), and `confirm` answers the open ask with the read-back answer only when his held reply carries its hash and doesn't say no (`saysNo`).
- botsun-owner: a reworded message confirmed by voice (feature `confirm_text`). `confirm {id, text, mode}` puts in the message Botsun read back, as a steer or a follow-up, never a stop, and only when his held reply carries `sha256("botsun-propose-text-v1\n" + text)` and says yes. At most 600 characters.
- botsun-owner: a signed `stop` request (feature `stop`) for the phone's Stop button; it ends the running turn as Esc does.
- stash: the stack lives in `lib/stash-store.ts`, so another extension (botsun-owner) can push, take and drop entries with the same file locking.
- footer: publishes its chips through `lib/footer-snapshot.ts` (`publishFooter`, ANSI split into coloured segments) for other extensions to mirror, and takes chip taps from them (`onFooterTap`; display toggles only).
- ask: a question can be answered from elsewhere. Each call offers its questions in `lib/remote-prompts.ts`; the TUI dialog and a remote answer race, and when the remote one wins the dialog closes and the tool returns what a keypress would have. botsun-owner answers from Eric's phone.
- footer: pace marks name the window. When a provider has more than one usage window (Codex, Claude, OpenCode Go), the arrow carries the window's span letter — `↓6w` is 6 points ahead of the weekly, `↓6h` of the 5h, `↓6m` of the monthly — in compact, detailed and mini (the bare `↓` becomes `↓w`); single-window chips (Copilot, Grok, Cerebras) stay bare. In mini the letter is the only window name there is.
- provider-usage: Claude's chip shows the meters of the model in use — the 5h session plus the weekly meter of the model's family (opus/sonnet), `weekly_all` when the family has none — instead of every weekly meter side by side; `/claude-window`'s detail still lists them all. The shared cache entry is keyed per family (`claude-window:opus`), so concurrent sessions on different families never adopt each other's value; canvas's usage table folds the family keys into one row, the freshest winning.
- footer: `defaultModels` in `footer.json` names each provider's everyday model (`{ "opencode-go": "deepseek-v4.1-flash" }`); with the Model condition at `unless default` the model chip hides for that model too. Hand-edited like `dirNames`, and kept when `/footer` saves.
- image-prune (opt-in): pi resends every image in context on every request until compaction, and base64 doesn't compress. Once the visible images pass `thresholdMB` (default 5), one batch of `context_edit` replacements at `turn_end` swaps every image older than the last `keepTurns` (2) user turns for a note with a path the read tool can open; pasted images are saved under `~/.pi/agent/tmp/image-prune/` first. One batch, not one image per turn, so the prompt cache is rewritten once. `/image-prune` shows the images in context; `/image-prune now` forces a batch. Tool result images over `shrinkMinKB` (512 KB) are also re-encoded on arrival to at most `shrinkMaxPx` (1568) and under 512 KB, with a note giving the coordinate scale: earl's 3.3 MB PNG camera photos become ~200 KB JPEGs.

### Changed

- canvas: the daemon no longer has a key. No route needs a cookie or `Authorization: Bearer`, `.daemon.json` holds only pid, port and version, `/canvas` and `/canvas url` use the plain URL, and the page has no "Canvas (locked)" state. An old `?k=` link redirects to the same URL without it. What stays: loopback only, the `Host` allowlist (DNS rebinding), no CORS headers, `frame-ancestors 'none'`, and the page's header and Origin on every POST. Anything local that can reach 127.0.0.1 can read sessions and type into pi; see "Access" in the canvas README. The tmux follow hook no longer needs to send a key.

- auto-bundle is now an opt-in extension (`/boehsline enable auto-bundle`), split out of the footer because it depends on a personal `~/bin/pi-bundle`. Behaviour when enabled is unchanged; it listens for the footer's version checks, which the footer now announces on `pi.events` as `boehsline:pi-version`, so it adds no `mise which pi` spawns. Without it enabled nothing re-runs pi-bundle.
- footer: drop the redundant `updateTimerStarted` flag; the update poll checks its own timer (pi rebinds extensions on every session switch).
- footer: OpenCode Go's provider chip reads `oc` (was `ocg`).
- provider-usage: drop the claude-bridge driver and its chip. It read Claude Code's own Keychain/OAuth credential to show the same windows `claude-window` already shows from pi's Anthropic login (`/login` → Anthropic).
- provider-usage: Claude reads the response's `limits[]` instead of inferring spans from `five_hour`/`seven_day`. Each meter names its own `kind`, `group`, `percent`, `severity`, and `resets_at`, so a new meter (Opus, Sonnet, cowork) needs no code, and only a meter with no reset is dropped. `is_active` flags which window is currently enforced, not whether it has usage — Anthropic reports `weekly_all` with `is_active: false` at 33% used — so it never gates rendering. A response where every meter lacks a reset reports `idle` instead of failing the fetch.
- footer, canvas: drop the retired claude-bridge special cases (`INLINE_STATUS_KEYS`, its provider abbreviation and model-name rule, and its canvas usage label). Canvas usage rows now name `claude-window` ("Claude") instead.
